\begin{abstract}
\noindent
This manual explains how to run genome scans that account for linkage
disequilibrium (LD) with \code{LDscnR-multi}, for one data set or for
hundreds in a batch. The workflow uses the \code{LDscnR} R package to group
correlated markers into Stage-1 units before testing, to assemble significant
units into outlier regions and to compare the number of significant Stage-1 units with a
structure-preserving permutation null. The examples use the full
three-spined stickleback panel (117 individuals and 790{,}578 markers) and
the full nine-spined stickleback panel (149 individuals and 1{,}195{,}557
markers) analysed in the LDscnR manuscript. Two-chromosome subsets of both
panels are included for a quick first run.
\end{abstract}

\section{Introduction}
% =============================================================================

\code{LDscnR-multi} is a workflow of R scripts, not an R package. You
install \code{LDscnR} from GitHub and then use this repository's scripts to
analyse one data set or a collection of data set folders. Each data set keeps
its own inputs and results, and a batch run also writes a combined summary.

As an example, on one core of an Apple M3 Pro laptop (36~GB memory, R~4.6.1), a complete
run took about 14 minutes for the three-spined panel (790{,}578 markers) and
about 28 minutes for the nine-spined panel (1{,}195{,}557 markers), with peak
memory use of 11 and 17~GB.
Section~\ref{sec:running} breaks these times down by step. The association
scan is fast because \code{emmax_fast()} reuses the fitted relationship model
for every marker or unit, whereas the Stage-1 LD calculations and the floor
profile take most of the time.

\subsection{What problem this workflow solves}

A genome scan for markers associated with a phenotype or an environmental
gradient faces a structural problem, because markers in LD with each other
are not independent tests. If every marker is tested, one underlying signal,
such as a genomic region with reduced effective gene flow between contrasting habitats due to local adaptation, can produce dozens or hundreds of significant
markers. Counting them separately exaggerates the number of associated
regions and increases the multiple-testing burden.

\code{LDscnR} addresses this in two stages. Stage~1 groups markers into
Stage-1 units from genotype LD alone, without the phenotype. Stage~2
assembles the significant Stage-1 units into outlier regions. For each data
set, \code{LDscnR-multi} runs these steps:

\begin{itemize}
  \item \textbf{Stage 1} (\code{build_stage1()}, Section~\ref{sec:stage1})
  fits the LD-decay curve, builds the Stage-1 units and the genomic relationship
  matrix (GRM) from one SNP from each of the Stage-1 units.
  \item \textbf{Association scan} (\code{run_stage_A()},
  Section~\ref{sec:scan}) uses EMMAX (efficient mixed-model association
  expedited; Kang et al.\ 2010) to test for genotype associations with a phenotype or environmental variable.
  EMMAX is a mixed model that accounts for
  relatedness and population structure through the GRM. The scan has two
  tests:
  \begin{itemize}
    \item the \emph{consensus} test (statistic \code{unit}) fits one
    association per Stage-1 unit, using a consensus genotype of its markers;
    \item the \emph{Simes} test (statistic \code{simes}) fits one association
    per marker and combines the marker p-values within each Stage-1 unit with
    Simes' method.
  \end{itemize}
  \item \textbf{Unit testing and Stage-2 assembly} (\code{run_stage_B()},
  Section~\ref{sec:unit-testing}) decides which Stage-1 units are
  significant and assembles them into outlier regions. It accepts the
  association scan's results or marker-wise p-values from any method,
  such as LFMM2 (latent factor mixed model; Caye et al.\ 2019).
\end{itemize}

The rest of this manual, which covers the LD-decay report, the
structure-alignment check, the floor profile and the Manhattan plots,
describes tools that support, calibrate or display these steps.

\subsection{Relationship to \code{LDscnR} and to the manuscript}

\code{LDscnR} supplies the clustering, association and outlier functions,
and \code{LDscnR-multi} organises them into a repeatable workflow for one or
many data sets. The example data are the stickleback panels analysed in the
LDscnR manuscript (Kemppainen and Guillaume 2026; Section~\ref{sec:cite}).

\subsection{Reusing previous results}

Every step records its inputs and settings and skips the work when nothing
has changed (Section~\ref{sec:receipts}). This helps both with one data set
and with large batches.

\subsection{Stage-1 clustering: units and \texttt{core\_snp}}

Before any association test, \code{LDscnR}'s
\code{ld_complexity_reduction()} groups markers into Stage-1 units from
genotype LD alone. The setting \code{cr_rho} (default 0.50) determines an
LD cutoff for each chromosome from its fitted decay curve. Single-linkage clustering first connects markers whose LD exceeds this cutoff,
then refines these groups
using complete linkage: every pair within a final unit must meet the cutoff.
Each unit has one representative
marker, its \code{core_snp}. The representative markers are used to match Stage-1 units across parameter settings, e.g.\ across floors,
and they also make up the ``LD-pruned'' data set for GRM estimation.
(Section~\ref{sec:floor-profile}). The index \code{unit_id} cannot be used
for this, because it counts only the units that reach a given floor.

\subsection{\texttt{ld\_w}: local LD support}
\label{sec:ldw-concept}

\code{ld_w} measures local LD support. For each marker, it is the median
$r^2$ with neighbouring markers inside a physical window derived from the
chromosome's LD-decay fit. The workflow fits
$r^2 = b + (c-b)/(1+a\cdot d)$ and uses the predicted decay rate
\code{a_pred} to set the window at $\rho = 0.95$. The resulting value is
reported as \code{ld_w_095}.

A high value means that the marker is strongly correlated with its local
neighbours; a low value means weak local correlation. The value is not a
distance, an association test statistic or a p-value. It depends only on the
genotypes and is reported alongside association results. The Manhattan plots
can show it in place of association p-values or q-values, which helps identify outlier regions that also have high local LD
(Section~\ref{sec:manhattan}).

\subsection{The floor: the minimum size of a tested unit}
\label{sec:size-floor-concept}

Not every Stage-1 unit is tested. The floor (\code{size_floor}) is the
minimum number of markers a unit must contain to be tested, and smaller
units get no unit-level p-value. This is the main mechanism by which the number of tests is reduced and makes the minimum
support of a tested unit explicit. The floor is never below two so unclustered markers (singleton clusters), which make up the majority of all SNPs, are never tested.
Unless it is set explicitly, it is derived from marker density, with one marker of
floor for every 250 markers per Mb of assayed sequence, rounded
(\code{size_floor_markers_per_mb} in \code{DEFAULTS}). Density is the number
of markers divided by the summed chromosome spans (\code{max(Pos) - min(Pos)},
in Mb). Using density reduces dependence on the number of chromosomes
analysed, although selecting chromosomes with different marker densities
can still change the floor. For these two-chromosome examples, the rounded
floor matches that of the full panel. The floor is 8 for the three-spined panel (about 2{,}080 markers per
Mb) and 12 for the nine-spined panel (about 2{,}960 markers per Mb). Small
units can still contain real signals, so raising the floor trades genomic
coverage for a smaller set of better-supported tests
(Section~\ref{sec:floor-profile}).

\subsection{Outlier regions: assembling significant units}

Stage~2 groups significant Stage-1 units into \emph{outlier regions}. A
region may contain one or more significant units and occupies one row of
\code{region_table.csv}
(Section~\ref{sec:unit-testing}). There are two assembly modes. The default,
\code{stage2_discovered}, repeats \code{LDscnR}'s clustering on the
significant units only, at its own LD threshold. The alternative,
\code{physical}, merges significant units whose spans lie within a set
distance of each other. The examples in this manual use the default, because it can separate physically overlapping regions that have different LD signatures.

\subsection{Permutation nulls and the permutation function}

The permutation null repeats the association scan with permuted phenotypes
to count how many significant Stage-1 units could arise without the
observed association.
\emph{How} the phenotype is permuted matters, because shuffling individuals
without regard to population structure can break the structure that the
mixed model is meant to account for. \code{LDscnR-multi} therefore requires
every data set with an association scan to supply its own \code{perm_fun.R}
(Section~\ref{sec:dataset-contract}) instead of assuming that a generic
shuffle is safe. The examples use a structure-preserving permutation that
reassigns whole populations' values among populations in the same structure
group (\code{perm_within_groups()}), as in the manuscript.

\subsection{The \code{LDscnR} version pin}
\label{sec:ldscnr-version}

The workflow checks the GitHub commit recorded in the installed package, not
only its version number, because package code can change without a version
bump. If the commit does not match the validated revision, the run stops
before it processes a data set. This prevents a large batch from mixing
results obtained with different package code. Reinstall the revision shown
above when that happens. Developers who work from a local checkout can set
\code{LDSCNR_DEV_LOAD_ALL=1}, and \code{LDSCNR_REPO} to the checkout's path,
before using \code{run_batch.R}. That mode loads the checkout and checks its
source instead. Ordinary users need neither a local \code{LDscnR} checkout
nor \code{devtools}.

\section{How many markers should be included?}
\label{sec:marker-density}
% =============================================================================

For most applications, we suggest starting with a well-spread panel of no
more than about \textbf{one million filtered markers}. This is a practical
target, not a biological or software limit. Only Stage-1 units that reach the
floor are tested, so adding many densely packed markers can lengthen the LD
calculations and the plotting without adding many distinct tests. The
nine-spined panel shows that 1.2 million markers are feasible, but it takes
longer and uses more memory than the three-spined panel.

If the starting panel is much denser, thin it \emph{before} you build the
input files. First apply the study's usual filters for missing data,
minor-allele frequency (MAF) and quality. Then use a recorded random seed to
sample markers across every chromosome and across short physical bins
within chromosomes, so that very dense bins are limited but every bin keeps
several markers. Set the bin width and the number of markers per bin from
the genome length and the desired total, so that coverage stays broad. Do not
select markers by their association with the phenotype, and do not keep only
one marker per Stage-1 unit, because that would defeat the unit-level test.
Apply the same selected marker IDs, in the same order, to
\code{genotypes.rds}, \code{map.rds} and any \code{external_pvalues/}
vectors. Record the filters, the seed, the binning rule and the number of
markers kept.

We recommend this binned sampling over simpler rules because it removes
markers mainly where they are redundant. Keeping every second marker, or a
random fraction of all markers, shrinks every Stage-1 unit by the same
proportion. Units in sparsely genotyped regions then lose markers they need
to reach the floor, whereas the dense bins that motivated the thinning still
contribute many markers. Capping the number of markers per bin instead
reduces the dense bins and leaves the sparse ones almost untouched, so the
loss of testable units is smaller for the same number of removed markers.
It is also where the time is saved. The cost of the early stages is set
mainly by the number of pairwise LD comparisons between nearby markers, which
grows faster than the number of markers in a dense bin, whereas the later
steps work only on the units that reach the floor and are fast.
Rules that keep markers at a minimum distance from each other, or LD pruning
that keeps one marker per correlated group, go too far in the other
direction, because they remove the correlated markers from which Stage-1
units are built. Random sampling within each bin, with a recorded seed, also
avoids any systematic pattern in which markers are kept and makes the
thinned panel reproducible.

Thinning \emph{can} change LD estimates, unit sizes and outlier regions. An
outlier region represented by too few remaining markers may disappear,
whereas the additional markers of an unthinned panel could have made its LD
pattern testable. When possible, therefore, compare the floor profile and
the main outlier regions on one representative denser data set before you
apply the thinning rule to hundreds of data sets. The one-million target is
not proof that denser data cannot reveal additional regions.

\code{external_pvalues/} is a second, optional folder next to \code{input/}.
It holds one \code{.rds} file per additional outlier method, each a \emph{named}
numeric vector (names are \code{map$marker}). The file name without
\code{.rds} is the method name, so \code{external_pvalues/lfmm.rds} is tested
as method \code{lfmm}. Unit testing does not care whether a p-value comes
from the association scan or from another method, as long as there is one
p-value per marker.

\subsubsection{A real \texttt{perm\_fun.R}}

The three-spined example's permutation function is shown below. The
phenotype (ecotype) is constant within each population, so a shuffle of
individuals would create variation within populations that never occurs in
the real data. This function instead reassigns which population gets which
value, among populations from the same locality.
\code{perm_within_groups()} (in \code{R/01_dataset_io.R}) visits populations
and groups in the same order as the manuscript's modules, so the same seed
gives the same permuted phenotypes.

\begin{Verbatim}
population <- readRDS(
  file.path(.dataset_dir, "input", "population.rds"))
structure_group <- readRDS(
  file.path(.dataset_dir, "input", "structure_group.rds"))
perm_fun <- function(b, y) {
  perm_within_groups(y, population, structure_group)
}
\end{Verbatim}

\subsection{\code{cache/} and \code{output/}: what the workflow writes}

Both folders can be deleted and rebuilt by rerunning the workflow, and the run records decide what needs
recomputing (Section~\ref{sec:receipts}).
\code{cache/} holds everything that depends only on the genotypes: the
genotype file in SNPRelate's GDS (Genomic Data Structure) format, the
LD-decay fit, the Stage-1 units and the GRM. There is no
\code{cache/edge_lists/}, because at full-genome density one chromosome's
pairwise LD edge list can take several gigabytes. Every step that needs an
edge list rebuilds it from the GDS file, one chromosome at a time, and
discards it after use. Section~\ref{sec:stages} describes \code{output/} step
by step, and Appendix~\ref{sec:appendix-tree} shows the whole tree.

\section{Running the workflow}
\label{sec:running}
% =============================================================================

The usual entry point is \code{run_dataset(dataset_dir)}, which runs every
applicable step, in order, for one data set. Start with the two-chromosome
examples in \code{examples/}, which take a few minutes. A full panel takes
minutes per step rather than seconds. Table~\ref{tab:timing} shows the times
of a complete run of each full panel from scratch, on one core of an Apple
M3 Pro laptop with 36~GB of memory and R~4.6.1. Peak memory use was 11~GB
for the three-spined panel and 17~GB for the nine-spined panel. Four cores
(\code{cores = 4}) shortened the three-spined run by only 13\%, to
12.5 minutes. Fitting LFMM2 to the three-spined markers, which is done
outside this workflow, took about 4.1 hours on one core. A second call on an
unchanged data set is fast (Section~\ref{sec:receipts}).

\code{run_dataset()} calls the following steps. Run records let the analysis
steps reuse results when their inputs and settings are unchanged; reports
and plots are regenerated.

\begin{enumerate}
  \item \textbf{Stage 1} (Section~\ref{sec:stage1}) clusters markers by LD
  from the genotypes alone. It is always called and reuses cached
  results when its inputs and settings are unchanged.
  \item \textbf{LD-decay report} (Section~\ref{sec:ld-decay}) writes out what
  Stage~1 computed. It rewrites the report on every run.
  \item \textbf{Structure-alignment check} (Section~\ref{sec:alignment}) runs
  only if both \code{input/population.rds} and \code{input/phenotype.rds}
  exist.
  \item \textbf{Floor profile} (Section~\ref{sec:floor-profile}) runs by
  default whenever \code{input/phenotype.rds} exists. It labels each outlier
  region by whether it is recovered at half and at twice the floor, but it
  does not change the reported floor.
  \item \textbf{Association scan} (Section~\ref{sec:scan}) runs if a
  phenotype is present.
  \item \textbf{Unit testing and Stage-2 assembly}
  (Section~\ref{sec:unit-testing}) runs once for each outlier method: the
  consensus and Simes tests of the association scan, and every file in
  \code{external_pvalues/}.
  \item \textbf{Manhattan plots} (Section~\ref{sec:manhattan}) are drawn as
  two figures with one panel per outlier method.
\end{enumerate}

\subsection{Stage 1: LD-based clustering}
\label{sec:stage1}

{\raggedright
\textbf{Function:} \code{build_stage1(dataset_dir, cfg)}.
\textbf{Depends on:} the genotypes and the map, not the phenotype.\par}

Stage~1 is the genotype-only foundation of every later step. It writes the
genotypes to a GDS file, fits the LD-decay curve
(Section~\ref{sec:ldw-concept}), computes \code{ld_w_095} for every marker,
runs \code{LDscnR::ld_complexity_reduction()} to group markers into Stage-1
units (\code{cr_rho}, default 0.50) and builds the GRM for the association
scan. The GRM uses the GCTA estimator (Yang et al.\ 2011) on the
representative marker of every Stage-1 unit, including single-marker units.
Stage~1 writes \code{cache/stage1.rds} and \code{cache/genotypes.gds}, and
every later step reads from them.

\subsection{Checking sensitivity to the minimum unit size}
\label{sec:floor-profile}

{\raggedright
\textbf{Function:} \code{run_floor_profile(dataset_dir, factors = c(0.5, 2))}.
\textbf{Runs when:} \code{input/phenotype.rds} exists, by default
(\code{floor_profile = TRUE} in \code{run_dataset()}).
\textbf{Writes:} \code{output/floor_profile/}.\par}

\Needspace{12\baselineskip}
\subsubsection*{Why the floor profile exists}

Any single floor (Section~\ref{sec:size-floor-concept}) is a practical
choice, so the floor profile asks how robust each outlier region is to that
choice. Every outlier region found at the reported floor is checked at half
and at twice that floor (4 and 16 for a floor of 8). It is labelled
\code{"3/3"} if it is recovered at both comparison floors, \code{"2/3"} if
it is recovered at one and \code{"1/3"} if it is recovered at neither. The
low comparison floor may be 1 (single markers included), but it is never
the reported floor.

In the manuscript's simulations (600 runs with known causal variants and a
floor of two), the precision of outlier regions was about 0.2 for regions
labelled 1/3, 0.5 for 2/3 and 0.8 for 3/3. These values held for the
consensus test, the Simes test and the Simes test on LFMM2 p-values, although
LFMM2 was somewhat lower (0.44 and 0.75 for 2/3 and 3/3). Dropping 1/3
regions cost little recall. Recovery at the \emph{lower} floor, where more
units are tested and the Benjamini-Hochberg (BH) threshold is harder to
reach, was the more informative of the two checks.

\Needspace{12\baselineskip}
\subsubsection*{How recovery is decided}

A region is recovered at a comparison floor when at least one of its
significant Stage-1 units is also significant at that floor \emph{and} the
region overlaps an outlier region assembled at that floor. This is the
manuscript's rule. Units are matched across floors by their representative
marker (\code{core_snp}, Section~\ref{sec:concepts}), because
\code{unit_id} only indexes the units that reach one floor and two different
units can both have the same \code{unit_id} at two floors. A unit smaller
than a comparison floor is not tested there, so it cannot be recovered
there.

\Needspace{12\baselineskip}
\subsubsection*{Only the reported floor gets permutations}

\begin{itemize}
  \item The \textbf{reported} floor runs the association scan and unit
  testing exactly as \code{run_dataset()} does, with the permutation null,
  Stage-2 assembly and, if an \code{annotation} is given, the relocation test.
  \item The two \textbf{comparison} floors are tested on the observed data
  only, using \code{observed_only = TRUE} in \code{run_stage_B()}. This
  mode never loads a permutation file. The consensus test is fitted once more, at the low floor
  (\code{run_stage_A(permute = FALSE)}). The units of the high floor are a
  subset of those of the low floor, and a unit's EMMAX p-value does not
  depend on which other units are tested. The high floor therefore reuses
  those p-values, and only the BH correction and Stage-2 assembly are
  repeated. The Simes test reuses the marker-wise scan at every floor.
\end{itemize}

gets the structure-preserving permutation null, and a region that persists
across floors can still be caused by population structure. The simulated
precisions make the label useful for ranking regions, but they are not a
calibrated probability that a region is true in a new data set.

\subsection{Association scan with EMMAX}
\label{sec:scan}

{\raggedright
\textbf{Function:} \code{run_stage_A(dataset_dir, cfg)}.
\textbf{Writes:} \code{output/pvalues/emmax_unit/} and
\code{output/pvalues/emmax_simes/}.\par}

Both tests use the same EMMAX mixed model, with the genotypes, the phenotype
and the GRM from Stage~1, but they test different things:

\begin{itemize}
  \item The \textbf{consensus test} (\code{unit}) fits one association per
  Stage-1 unit that reaches the floor, using a consensus genotype of the
  unit's markers (\code{unit_repr = "consensus_dosage"}). It writes
  \code{p_obs.rds} and \code{p_perm.rds}, with one value per tested unit,
  and \code{p_obs_marker.rds}. The last is a separate marker-wise EMMAX scan,
  used only so that the Manhattan plot shows variation between markers
  rather than one flat value per unit.
  \item The \textbf{Simes test} (\code{simes}) fits one association per
  marker and combines the p-values within each unit that reaches the floor
  with Simes' method. It writes \code{p_obs.rds} for \emph{every} marker,
  which the plots need, and \code{p_perm_compact.rds}, the permutations for
  the markers in tested units only. In the full three-spined panel only
  about 2.1\% of the 790{,}578 markers belong to units of at least eight
  markers, so restricting the permutations saves most of their cost. The
  results are identical to an unrestricted scan. \code{run_stage_A()} takes
  \code{simes_floor} (by default the floor), and a later call with a lower
  floor rebuilds this scan.
\end{itemize}

With \code{input/covariate.rds}, the phenotype and every permuted phenotype
are residualised on the covariate before EMMAX. Both folders also hold
\code{params.rds} and the run record \code{_receipt.rds}
(Section~\ref{sec:receipts}). The outputs are R objects, and
Section~\ref{sec:unit-testing} shows what they become after unit testing.

\subsection{Unit testing and Stage-2 assembly}
\label{sec:unit-testing}

{\raggedright
\textbf{Function:} \code{run_stage_B()}, once per outlier method, called as\newline
\code{run_stage_B(dataset_dir, engine, cfg = cfg)}, where the argument
\code{engine} names the method.
\textbf{Writes:} \code{output/stageB_<method>/}.\par}

This step turns p-values into decisions. It decides which Stage-1 units are
significant after BH correction and assembles them into outlier regions. It
also runs a permutation test when permutation p-values are available.
This compares the observed number of significant units with the counts for
permuted phenotypes. An external file of observed marker p-values alone
does not supply a permutation null; pass permutation p-values to
\code{run_stage_B()} to test that method against its own null. If an
annotation is given, this step also runs the relocation test. The relocation test moves the
outlier regions to random positions within their chromosomes (10{,}000
relocations) and asks whether they overlap the annotation more often than
expected. Unit testing and Stage-2 assembly use the same procedure for every outlier method,
whether it is the
consensus or Simes test of the association scan or a file in
\code{external_pvalues/}. The full three-spined panel has an
\code{external_pvalues/lfmm.rds}, so unit testing runs three times
(\code{emmax_unit}, \code{emmax_simes} and \code{lfmm}). It gives
50 outlier regions for LFMM2, compared with 39 for the
consensus test and 35 for the Simes test, with the same columns and
meaning.

\subsection{Manhattan plots}
\label{sec:manhattan}

{\raggedright
\textbf{Function:} \code{ldm_manhattan(dataset_dir, engines, value)}.
\textbf{Writes:} \code{output/figures/}.\par}

The Manhattan plots show $-\log_{10}(q)$ (\code{value = "q"}),
$-\log_{10}(p)$ (\code{value = "p"}) or untransformed local LD support
(\code{value = "ld_w_095"}). The association axes use the marker display
values \code{q_display} and \code{p_display}, while significance and
region membership are decided from unit-level q-values. A coloured marker
can therefore have a display q-value above the unit-testing threshold. The plot of \code{ld_w_095} lets you compare an
outlier region with the local LD pattern, but it is not a second association
test.

Each outlier method gets one panel, and all panels share one continuous genome-wide
axis, with chromosomes placed end to end and marked by alternating light-grey
bands. Markers outside outlier regions form a grey background, and markers
in outlier regions are coloured by region. Nearby regions get contrasting
colours. The strongest regions in each panel are labelled directly rather
than through a legend. When a floor profile (Section~\ref{sec:floor-profile})
exists for a panel's test, the label also shows the tier, for example
\code{"R5 (3/3)"}. External methods have no floor profile and keep plain
labels.

\section{Caching and run records}
\label{sec:receipts}
% =============================================================================

Several steps take minutes to hours, so the workflow does not repeat a step
whose inputs and settings have not changed. To know this, each analysis step
(Stage~1, the association scan, unit testing for each outlier method and the
structure-alignment check) writes a run record next to its output, in a file
named \code{_receipt.rds}. The run record lists the input files, the
settings and the output files of the step, together with a hash of each. A
hash is a short fingerprint computed from a file's contents, so any change
in the contents gives a different hash. When the step is called again, it
compares the current hashes with those in the run record. If they all match,
it reuses the saved results instead of recomputing them. The floor profile
and the floor sweep are made of these steps, so they use the same run
records.

Because the hashes are of file \textbf{contents}, not timestamps, a
\code{git checkout} or a copied file cannot hide a change in contents.
Unchanged runs still read the input and cached files to check their hashes.
The LD-decay report is rewritten, and plots are redrawn unless
\code{plot = FALSE}.

A run record is also out of date when one of its recorded outputs is missing
or when the validated \code{LDscnR} revision has changed. The run record of
the association scan also depends on the Stage-1 run record, and unit
testing records the contents of any p-values or annotation passed to it
directly. Pass \code{force = TRUE} to an analysis step only when you want to
rebuild its results although the inputs and settings are unchanged.

\section{Reproducing the manuscript}
\label{sec:reproduce}
% =============================================================================

\code{manuscript/} runs this workflow on the two full stickleback panels of
the manuscript and compares every result with the manuscript's analysis
modules (\code{module_3sp} and \code{module_9sp} in the LDscnR-paper
repository). The default settings already match the modules' settings
(Table~\ref{tab:repro}). The nine-spined panel adds \code{covariate.rds}
(lineage), and both panels permute populations within groups with
\code{perm_within_groups()}.

\small
\captionof{table}{Settings shared by the manuscript and the defaults of
\code{LDscnR-multi}.}\label{tab:repro}
\begin{tabular}{@{}L{5.0cm}L{9.0cm}@{}}
\toprule
\textbf{Setting} & \textbf{Value} \\
\midrule
Stage-1 LD setting & \code{cr_rho = 0.50} \\
LD-decay window (\code{slide}) & 500 markers \\
GRM & GCTA, from the representative marker of every Stage-1 unit \\
Floor & marker-density rule (8 for three-spined, 12 for nine-spined) \\
Permutations & 1{,}000 (consensus) and 200 (Simes) \\
EcoPeak relocation test & 10{,}000 relocations within chromosomes \\

  Section~\ref{sec:floor-profile} \\

\bottomrule
\end{tabular}
\end{minipage}\par\medskip

The scripts need the modules' Stage-1 bundles and data from a local
LDscnR-paper checkout (environment variable \code{LDSCNR_PAPER}). Without
them, \code{manuscript/} documents the reproduction but cannot rerun it.

\begin{Verbatim}
Rscript manuscript/build_inputs.R    # data set folders from the module bundles
Rscript manuscript/run.R             # all steps, including the floor profile
Rscript manuscript/compare.R --out=manuscript/comparison_vs_v091
\end{Verbatim}

\code{manuscript/run.R} calls the workflow's steps directly, without the
Manhattan plots and the structure-alignment check. For a new data set, the
entry point is \code{run_dataset()} or \code{run_batch.R}. For the
three-spined panel, \code{run.R} also runs the EcoPeak relocation test on
every outlier method's outlier regions and on each floor-stability tier. EcoPeaks are
the marine-freshwater differentiated regions of Kingman et al.\ (2021).

\code{manuscript/comparison_vs_v091.md} lists every check. With LDscnR v0.9.1, all 108 checks match the modules' results: the
Stage-1 units, the GRM, the LD-decay fit, every unit p-value, the significant
units, the outlier-region spans, the permutation counts, the EcoPeak
relocation tests, the floor-stability tiers and the EcoPeak tests per tier.
\code{manuscript/comparison_vs_stored.md} compares with the modules' earlier
outputs from LDscnR commits before v0.9.1. It matches except for the EcoPeak
relocation null mean, fold and p of the three three-spined tests (9 of 108
checks), which changed because v0.9.1 keeps relocated regions inside their
chromosome.

The LFMM2 p-values are not computed here. \code{manuscript/build_inputs.R}
converts the manuscript's stored LFMM2 F statistics
(\code{LEA::lfmm2.test()}, $K = 7$) to p-values with
\code{pf(F, 1, n - 2)}, exactly as the modules do. The stored F statistics are
already divided by the genomic inflation factor (their median equals the null
median exactly), so these p-values are genomic-control corrected.

\section{Known limitations}
% =============================================================================

\begin{itemize}
  \item \textbf{Plotting at genome scale.} \code{ldm_manhattan()} plots
  every marker. Figures~\ref{fig:manhattan-q} and~\ref{fig:manhattan-ldw}
  show that this works for a full panel of 790{,}578 markers, but a much
  larger panel would benefit from thinning or rasterising the points.
  \item \textbf{One data set folder per genotype panel and phenotype.}
  Screening many phenotypes on the same genotype panel needs one folder per
  phenotype. Each folder then rebuilds the same Stage~1 and stores its own
  copy of \code{genotypes.rds} and \code{map.rds}. This is fine when the data
  sets are different genomic panels, but it is costly for many phenotypes on
  one panel, and sharing Stage~1 between phenotypes would need a change of
  design.
  \item \textbf{Scope.} Unit testing accepts p-values from any method, but
  the workflow runs only \code{LDscnR}'s own outlier analysis. It has no
  interface for other outlier methods, such as OutFLANK, BayeScan or
  pcadapt.
\end{itemize}
